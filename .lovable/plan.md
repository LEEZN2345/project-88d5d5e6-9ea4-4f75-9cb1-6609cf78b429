# 东大门订货通 · 研发计划

## 一、产品定位(待你补充确认)

**一句话定位**:为东大门买手与 B 端客户提供东大门档口的全量商品信息,新款抢先、折扣促销,边逛边加购、一键下单、一键发货、全程物流跟踪。

- **目标用户**:
  - **B 端(主)**:实体服装店主、东大门职业买手、时尚自媒体/KOL、跨境电商卖家、直播带货主播
  - **C 端(辅)**:有购买力的个人时尚消费者(直接零售,客单价较高)
  - 双轨定价与权限:B 端走批发价/账期/混批,C 端走零售价/单件下单,同一商品两套价格视角
- **核心价值**:
  1. **全量货源**:覆盖东大门档口的完整 SKU,而不是片段化转发
  2. **新款抢先**:档口上新即同步,首屏推荐与订阅提醒
  3. **折扣促销**:档口活动、清仓、阶梯价集中曝光
  4. **边逛边加购**:多档口共用购物车,选款流即是下单流
  5. **一键下单 / 一键发货**:打通档口下单 → 韩国仓集货 → 国内发货
  6. **全程物流跟踪**:档口出货、仓内分拣、跨境运输、国内派送统一时间线
- **平台形态**:同一套响应式 Web,移动端为主、PC 端兼顾
- **语言/币种**:中韩双语,KRW ↔ CNY 实时汇率换算,下单锁定汇率快照

## 一·B 商业模式(三层收入结构)

1. **基础物流服务费(主力现金流)**
   - 按订单/件数/重量/体积计费,覆盖韩国仓集货、打包、跨境运输、国内派送
   - 建议结构:打包费(按件)+ 头程运费(按重/体)+ 国内派送费,平台抽取固定毛利
   - 在下单页透明显示费用明细,与商品款单分开结算,降低买手心理摩擦
2. **增值服务费(按需付费,做利润)**
   - 验货 / 质检 / 称重拍照
   - 加固包装 / 防潮 / 重新分箱 / 贴 SKU 唛头
   - 退换货代办、瑕疵索赔代谈、补单催货
   - 财务代付韩币、垫付货款(短期账期 / 资金成本)
   - 翻译沟通、档口砍价、专属采购员
3. **SaaS 会员费(锁定 B 端高频用户,做 LTV)**
   - 免费版:基础浏览 + 下单 + 标准物流
   - 会员版(月/年订阅):新款抢先推送、折扣专享、批量下单/导入、对账报表导出、专属客服、降低物流/服务费率、批发价开放、账期额度
   - 团队版:多账号协作(老板 + 采购 + 财务)、权限分级、店铺数据看板

> 设计含义:订单与账单模型必须区分 **货款 / 物流费 / 增值服务费 / 会员费** 四类流水,分别开票与对账;权限系统要支持"会员等级 → 价格视角 / 费率 / 功能开关"。

> 待你补充:目标用户更细颗粒(单兵代购 vs 批发商占比)、首批种子档口与种子买手获取方式、与现有竞品(韩都依舍、东大门 Buy 等)的差异承诺。

## 六、关键风险与决策点(请你在讲定位时一并回答)

1. **货源数据**:运营员工后台手动维护(不开放商家自传图),需要批量上传 + 款号去重 + 水印工具。
2. **资金与通关**:多个个人微信/支付宝收款 + 自有通关渠道,定位为「个人之间的代购服务」,不占用个人 5 万额度。账单只做内部对账,不开企业发票。
3. **价格与汇率**:商品价以 KRW 为准,RMB 结算按当天汇率(下单/付款时锁汇率快照,留差额字段)。
4. **退款**:全部走人工审核 → 个人账户原路退回,系统需要审核工单 + 退款流水登记。
5. **物流**:自有团队对接通关社,运单状态走 Excel 批量上传(系统需提供导入模板 + 解析 + 异常报告)。
6. **角色**:首期只做 B 端,客户内部分工通过微信群沟通,平台账号暂不细分子角色(老板/采购/财务合一)。

## 七、由你的回答推导出的设计调整

- **收款账户池 + 日额度自动切换**:后台维护多个收款人(微信/支付宝二维码 + 户名 + 日收款上限),下单分配时按当日累计实收金额自动跳过已达上限的账户,达上限自动切换到下一个可用账户;后台提供「账户管理」页:增删账户、设/调上限、查看今日累计、手动停用/启用、流水查询、风控记账(冻结/限额历史)。订单登记「实收账户 + 流水号 + 付款凭证截图」。
- **内部款号即唯一商品 ID**:不做 SPU/Variant 拆分,一个内部编号 = 一个商品,后续不同色/尺码若需要再独立录一个款号。商品表用 `internal_code`(唯一索引)作为业务主键,档口原始款号作为参考字段保存。
- **汇率快照在「平台代付完成」时锁定**:下单/加购阶段仅按当日参考汇率展示,真正写入 `order.snapshot_rate` 的时点是运营在后台标记「已代付韩币」之后;同时上传付款小票(收据/转账截图)到 `order.payment_receipt_url`,买手在订单详情页可查看。
- **不做商家入驻**:删除「商家后台」相关页面,只保留「运营后台 → 商品/档口录入」。前期录入工具优先级提高(批量粘贴/Excel 导入/图片批量拖拽 + 自动加水印)。
- **退款工单两级审核**:`refund_requests` 状态机:`待客服提单 → 待财务复核 → 已打款 / 已驳回`;两级操作人分别记录(`cs_user_id` / `finance_user_id`),退款金额、退款账户、退款流水号、回执截图必填。
- **物流批量导入**:运营后台提供「物流单 Excel 上传」入口,**模板字段(v1)**:`订单号 | 运单号 | 物流商 | 当前节点(韩国仓入库/打包出库/起运/到港清关/国内派送/已签收) | 节点时间(YYYY-MM-DD HH:mm) | 备注`;解析后写入 `shipment_events`,异常行打包成错误报告 Excel 返回下载。模板后续可加字段,先按此版本落地。
- **角色精简**:前期 2 个业务角色 —— `customer`(B 端买手) + `ops`(平台员工);`ops` 内部权限通过功能开关而非子角色控制,但财务/客服两类操作通过「权限点」区分(影响退款两级审核谁能点哪步)。

## 七·C 邀请分销与阶梯费率(M2)

### 1. 档位表(最终版)

| 有效下线数 | 服务费 | 运费(₩/kg) | 说明 |
|---|---|---|---|
| 0(凭邀请码注册) | 3.5% | 9500 | 受邀新客默认入门档 |
| 1 | 3.0% | 9500 | 种子用户标准 |
| 2 | 2.8% | 9500 | |
| 3 | 2.7% | 9500 | |
| 4 | 2.6% | 9500 | |
| 5+ | 2.5% | 9500 | 最低封顶 |

- 档位**只降不升**,不再设回退兜底。
- 邀请码由**平台统一生成**并下发,非平台生成的邀请码无效。
- 散客(无邀请码)沿用默认 4% / 9800,不进入分销体系。

### 2. 「有效下线」判定

- 定义:某下线在**滚动 90 天内**累计补货金额 ≥ **500 万 KRW**(以「平台已代付完成」金额为准,不扣退款金额 —— 本场景无退款)。
- 一旦达标,下线即记为该邀请人的 1 个有效下线;滚动窗口外金额掉出后,该下线状态会回落为「未达标」,但**邀请人档位本身不上调**。
- 邀请人当前有效下线数 = 当前仍处于「滚动 90 天 ≥ 500 万」状态的下线数。
- 触发降档时间:**北京时间次日 00:00** 全量复算并生效。

### 3. 继承与传递规则

- 新下线无论邀请人当前档位多低,**一律从 3.5% 起步**,自己拉够 1 人才进 3.0% 种子档。
- 邀请人的档位只作用于自己的服务费/运费,**不下沉、不继承**给下线。
- 下线的补货金额只计入「该下线对其邀请人」的有效下线判定一层,不向上多级累计。

### 4. 反作弊与风控

- 关联账号判定:同设备指纹 / 同收货地址 / 同微信支付实名 / 同 KYC 身份证,命中任意 2 项即判定为关联账号,关联账号之间互邀**不计入**有效下线。
- 邀请码仅平台后台生成,运营按申请审核发放;客户不能自助生成邀请码,杜绝批量灌水。
- 后台保留「人工冻结/手动调整档位」开关,用于异常案件处置。

### 5. 时区与展示

- 全部档位计算与切档动作按**北京时间(UTC+8)**执行,前端在档位卡片同时展示「下次复算时间:北京时间次日 00:00」。
- 韩币付款小票时间仍按 KST 展示,两者明确区分,避免买手误读。
