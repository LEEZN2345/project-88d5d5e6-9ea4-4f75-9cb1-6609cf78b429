# 注册 & 会员开通流程重设计

## 现状
- `/auth` 只是一个手机号 + 验证码的极简登录框，没有任何权益展示。
- `/membership` 已经维护了完整的三档权益对比表（游客 / 普通 ¥99 / 创作者 ¥199）。
- 现有逻辑：游客也能下单，但拿不到积分、无返佣、满 ¥300 才免运。付费会员才是主要收入 + 留存杠杆。

## 目标
让新用户在注册那一刻就"看得见值不值"，并且能一步开通付费会员，而不是先注册 → 再自己去「我的 → 会员」翻半天。

## 设计方案（分 3 步的注册漏斗）

### Step 1 · 权益前置的落地欢迎页 `/auth`
把当前的单一登录框改成"上半屏卖点 + 下半屏手机号"结构：

```text
┌────────────────────────────┐
│  东大门订货通                │
│  为东大门买手 & B 端而生     │
│                            │
│ ┌────────────────────────┐ │  ← 3 张横向滑动的权益卡
│ │ 全场包邮  9.5 折专享    │ │     (从 membership 的 RIGHTS 精选)
│ │ 3% 创作返佣 可提现     │ │
│ │ 开卡送 1000~3000 积分  │ │
│ └────────────────────────┘ │
│                            │
│  [ 手机号            ]      │
│  [ 验证码            ]      │
│  ( 主 CTA )  注册并选会员   │  ← 主按钮改文案
│  ( 次 CTA )  先以游客登录   │  ← 弱化的文字链
│                            │
│  登录即同意 服务协议 / 隐私  │
└────────────────────────────┘
```

行为：
- 主 CTA：完成手机号验证 → 直接跳 Step 2 选会员页。
- 次 CTA "先以游客登录"：完成手机号验证 → 落到首页，但在首页顶部持续挂一条"升级享全场包邮"的软性提示条（可关闭）。
- 已注册用户识别：手机号已存在 → 视为登录，若已是会员直接进 `/`，若还没开通会员则同样进 Step 2。

### Step 2 · 会员选择页 `/auth/plan`（新页面）
复用 `/membership` 的数据源（`PLANS`、`RIGHTS`），但以"注册漏斗"的视觉呈现：

- 顶部："欢迎，138****8888 🎉 选择你的会员身份"
- 3 张并排卡：**游客 ¥0** / **普通 ¥99** / **创作者 ¥199**
  - 默认高亮"创作者会员"（推荐 + 一句 ROI 提示："自购 ¥6,700 即回本"）
  - 每张卡列 4 条最抓眼的权益（免运费 / 返佣 / 提现 / 开卡礼）
  - "查看完整对比" → 展开 `/membership` 完整表格（同页 Sheet 弹层，不跳走）
- 底部粘性 CTA：
  - 选中"游客"→ 按钮变"以游客身份开始逛"，跳首页。
  - 选中"普通/创作者"→ 按钮变"¥99 立即开通 / ¥199 立即开通"，进入 Step 3 支付。

### Step 3 · 支付页 `/auth/pay`（复用现有 checkout 组件）
- 15 分钟支付倒计时（沿用 `checkout` 现有兜底逻辑）。
- 支付成功 → 落"开卡成功"页：展示到账积分 + "去发第一篇好物 / 去逛首页"两个引导。
- 支付失败 / 取消 → 退回 Step 2，会员身份保持"游客"，用户依然是已注册状态，可随时从 `/me → 会员卡区` 再次开通。

## 关键规则 & 兜底
- **注册与开通解耦**：会员支付失败不影响账号已注册这个事实。数据层用户表的 `membership_tier` 默认 `guest`，支付回调成功后升级为 `normal`/`creator`。
- **游客也能用**：不做强制付费墙，符合当前"游客可下单但满 ¥300 才免运、无返佣"的逻辑。
- **发帖 & 提现拦截点保留**：Step 2 跳过的游客用户，走到 `/discover/new`（需普通会员）和 `/withdraw`（需创作者会员）时，弹层引导"升级即可解锁"，直接把他们再拉回 `/auth/plan`。
- **续费入口**：`/me` 会员卡到期前 30 天出现"续费 ¥99 / ¥169"角标，点击复用 Step 3 的支付页。

## 技术改动清单
1. 改写 `src/routes/auth.tsx`：顶部权益轮播 + 双 CTA。
2. 新增 `src/routes/auth.plan.tsx`：三卡会员选择页，`PLANS` / `RIGHTS` 从 `membership.tsx` 抽到 `src/lib/membership.ts` 作为共享数据。
3. 新增 `src/routes/auth.pay.tsx`：调用现有 `checkout-store` 的支付流程 + 成功页。
4. `src/lib/auth-role.ts`（或用户信息 store）里加 `membershipTier: 'guest' | 'normal' | 'creator'` + `membershipExpireAt` 字段，并暴露 `upgradeMembership(tier)` mock 方法。
5. 在 `/discover/new`、`/withdraw`、`/commission` 等已限制入口，把"未开通"提示的按钮统一指向 `/auth/plan`。
6. `/me` 会员卡区读取新的 tier 字段渲染当前身份 + 到期日 + 续费按钮。

## 不做的事
- 不改积分 / 返佣 / 结算等业务规则（沿用现有 3% / 0.5% / 0.2% / T+14 逻辑）。
- 不接真实支付网关（本轮仍是前端 mock，只把状态机和引导链路打通）。
- 不动 admin 侧，会员开通记录后续在后台 `/admin/membership` 里补统计即可。
